### 第 2 页：研发痛点洞察与业界方案瓶颈
- **标题**：为什么持续集成（CI）依然是现代软件工程的「效率黑洞」？
- **三联图解对比**：
  1. **痛点 1：日志浩瀚，排查耗时耗力**：
     - 现代 CI 构建产生的测试与静态分析日志常达数千行，开发者平均需要耗费 15～45 分钟逐行翻找有效崩溃帧与调用栈。
  2. **痛点 2：单体 Copilot/Cursor 盲目生成代码，次生破坏率高达 23.5%**：
     - 现有单体 LLM 仅在编辑器端“猜代码”，缺少环境感知与真实回归闭环。“修好了一个 Bug，却破坏了既有三个正确用例”。
  3. **痛点 3：上下文无节制膨胀与无状态记忆缺失**：
     - 将整文件盲目塞入 Prompt 导致 Token 消耗急剧膨胀（单次 12,000+ Tokens），更引发严重幻觉；同一类越界或除零错误在不同仓库反复被踩坑，智能体无法沉淀知识。
- **结论引出**：业界亟需一套兼备**确定性图编排**、**多角色隔离制衡**、**严格安全沙箱回归**与**终身经验自进化**的系统级工程解决方案。

| 技术需求 | 传统 LangChain / AutoGen 方案 | openJiuwen + JiuwenSwarm 原生架构 | 本作品落地体现 |
|:---|:---|:---|:---|
| **执行流控** | 链式黑盒调用，分支条件不可控 | **有向无环计算图 (DAG)** 确定性状态机 | `HealSwarmFlow` 四阶段确定性图流转 |
| **角色协同** | 扁平多 Agent 容易发散与死循环 | **Leader-Teammate** 阶层分工与仲裁制 | `SwarmLeader` 任务拆解与 4 大 Teammate 协同 |
| **沙箱安全** | 本地直接覆写，存在越权安全风险 | 资源隔离与严格路径白名单管控 | `SandboxVerifier` 临时安全沙箱与语法预审 |

- **一句话总结**：openJiuwen 赋予了系统坚固如磐石的图计算执行底座，JiuwenSwarm 赋予了智能体群体专业分工与经验进化的智慧灵魂。

### 第 4 页：总体架构设计与双工作流动态路由
- **标题**：分层拓扑架构与 Multi-Workflow 动态自适应调度
- **Mermaid 架构全景图展示**：
  - **接入层**：CLI 终端（`demo` / `heal` / `inspect` / `benchmark` / `dashboard`）与 Webhook 事件触发器；
  - **主控层**：`SwarmLeader` 控制器，具备意图识别（Intent Recognition）、任务拆解（Task Decomposition）与状态遥测（Trace Telemetry）；
  - **编排层**：双工作流路由体系：
    - `InspectFlow`（快速诊断流）：`Start -> triage -> inspect -> End`，毫秒级快速切片；
    - `SwarmFlow`（全自愈闭环流）：`Start -> triage -> inspect -> verify -> evolve -> End`，驱动隔离沙箱验证与知识蒸馏。
  - **生态层**：贯通 openJiuwen 六大核心抽象（`Workflow`, `WorkflowCard`, `LLMComponent`, `WorkflowAgent`, `ReActAgent`, `Runner`）。

### 第 5 页：四大领域智能体 Teammate 深度拆解
- **标题**：术业专攻 —— 四大 Teammate 智能体协同闭环
- **四大工具核心卡片**：
  1. **Log Triage Teammate**：
     - 正则语法状态机过滤 ANSI 干扰，精准回溯定位责任源码帧，计算故障 SHA-1 唯一语义指纹；
  2. **Code Inspector Teammate**：
     - 基于 Python `ast` 抽象语法树精准切片 Enclosing Scope（函数/类），提取 Top-Level 依赖与调用拓扑，上下文 Token 压缩 77.2% 以上；
  3. **Sandbox Verifier Teammate**：
     - 严格路径白名单防御穿越攻击，临时工作区隔离运行原子补丁，AST 语法预审与轻量快照保证 0 次生破坏；
  4. **Skill Evolver Teammate**：
     - 多 Bug 独立蒸馏，双模持久化至 `learned_patterns.json` 与 `ci_healing_memory.md`，置信度阈值动态准入。

### 第 6 页：多轮 ReAct 级联自纠错与双模优雅降级容灾
- **标题**：高可用容灾与复杂缺陷级联收敛
- **两大核心技术突破**：
  1. **多轮 ReAct 级联自纠错闭环**：
     - 针对同一模块多个交织 Bug（例如 `find_max` 越界与 `average` 除零），沙箱回归失败后捕获新报错，增量回传规划节点，多轮迭代直至用例 100% 变绿；
  2. **双模动态降级与容灾熔断（Graceful Degradation）**：
     - **Live LLM 模式**：调用 DeepSeek / OpenAI 兼容接口，若网络超时、鉴权异常或生成代码语法非法，自动触发熔断降级；
     - **Deterministic Replay 模式**：无缝回退至本地规则引擎与 AST 守卫，保证断网评审与干净 CI 环境 100% 零崩溃。
